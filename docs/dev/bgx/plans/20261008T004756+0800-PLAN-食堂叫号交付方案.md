## 2. 运行环境（拟议）

- 一台或两台校园服务器 / 虚拟机；操作系统不锁。
- 进程：Nginx、**Go API 二进制**（可 2 副本）、PostgreSQL、Redis、静态 Web。栈为方案 C，不假设 Node 运行时。
- 浏览器：用餐者现代手机浏览器；员工/管理 Chrome 或 Edge 近两个大版本；大屏同样。
- 校园网内网优先；HTTPS 证书来源待运维提供（未提供则内网 HTTP 仅限演示，不得当生产）。
- 容量目标 2000–3000 WS：**待实测**，机器规格不在此编造。

## 3. 上线前配置与凭据

- 管理员初始账号：首次用环境变量或一次性 setup，随后改密。
- 导入学号名单：CSV 模板（学号、姓名可选、初始密码策略）。真实学生数据导入需学校授权。
- 窗口 skip_timeout_seconds 默认 0。
- 大屏：每窗一条可吊销展示链接；电视记住链接，避免员工账号挂在公共屏上。
- 时区：Asia/Shanghai，与营业日一致。

外部动作（需另授权）：采购/安装电视、防火墙放行、域名、把学生名单交给系统。

## 4. 安装 / 升级（计划）

1. 准备 Postgres、Redis、Nginx。  
2. 填环境变量（数据库 URL、JWT 密钥、初始 admin）。  
3. 迁移 schema。  
4. 启动 API 与静态资源。  
5. 用演示账号走 T16 脚本。  

升级：先备份库 → 跑新迁移 → 发 API/Web → 冒烟 B01/B02。  
迁移失败则停升级，不自动修库。禁止在业务失败分支临时 ALTER。

尚无具体 compose 文件；T18 实施时补真实命令。不能把「目录将存在」写成已安装。
