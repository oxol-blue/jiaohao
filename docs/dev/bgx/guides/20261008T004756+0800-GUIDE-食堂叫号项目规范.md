## 3. 拟议目录（尚无代码，路径均为拟定）

推荐 **模块化单体**：一个 API 进程 + 一个 Web 前端（按角色路由）+ 大屏路由。少部署单元，便于第一期上窗。

```text
apps/web/                 # Vue 3 + Vite：用餐者 / 员工 / 管理员 / 大屏（路由隔离）
apps/api/                 # Go + chi：HTTP + WebSocket，模块化单体
api/openapi.yaml          # HTTP 合同权威（错误码、DTO、路径）
docs/dev/bgx/             # 本技能资料
```

主栈为 Go + Vue 3：不能假设一份 TypeScript 类型同时给两边编译。错误码与事件名只在 OpenAPI / SPEC 出现一次。

备选：四端拆成四个前端应用。仅当单仓前端构建明显拖垮或权限打包需要物理隔离时再拆。

模块在 `apps/api` 内按职责分目录，不按层把业务拆散：

- `identity`：账号、会话、角色
- `canteen`：食堂、楼层、窗口主数据
- `queue`：取号、叫号、过号、取消；**队列权威写入口**
- `realtime`：WebSocket 订阅与广播，不拥有队列状态
- `admin`：导入、授权、过号时长配置（写 canteen/identity，不直接改 ticket 状态，除非明确的运维重置接口）

## 4. 命名

- 需求 Rxx、任务 Txx、阶段 Sxx、链路 Bxx、决定 Dxx 沿用已有 ID，不复用已关闭 ID。
- API 路径：`/api/v1/...`，资源用复数名词。
- 事件名：`queue.ticket.called` 这类过去式，不发明第二套。
- 数据库表：蛇形复数 `tickets`、`windows`。
- 日志字段：驼峰或蛇形选一种后冻结；推荐蛇形 `request_id`。

## 5. 角色与前端边界

| 角色 | 入口（拟定） | 可调用 |
| --- | --- | --- |
| diner | `/` | 登录后浏览、取号、我的号、取消等待中 |
| staff | `/staff` | 被授权窗口的叫号动作；打开本窗口大屏 |
| admin | `/admin` | 主数据、账号导入、过号时长、员工授权 |
| display | `/display/:windowId` + 展示令牌 | 只读订阅；**不授予叫号权**；无有效令牌不可用 |

前端只做输入、展示、薄编排。队列规则、一人一号、号段分配只在 `queue` 模块执行。大屏不得持有员工令牌。

## 6. 数据所有者

- **窗口/食堂主数据**：`canteen` 写，其它模块只读。
- **账号与授权**：`identity` 写。
- **票号与队列状态**：仅 `queue` 写。Redis 里的人数/当前号是投影，失效以 DB 为准。
- **实时连接**：`realtime` 拥有连接生命周期，不持久化业务状态。

禁止 UI 或网关自行增减号、改人数。

## 7. 日志与排错

每条业务写操作打一条可查询日志，至少含：

`ts, level, request_id, user_id, role, window_id, ticket_id, event, outcome, error_code`

- 密码、令牌明文禁止入日志。
- 取号/叫号/过号/取消必须能用 `ticket_id` 或 `(window_id, business_date, number)` 找回。
- 开发默认 stdout JSON；生产文件或平台 sink 待部署时定，不在规范里锁厂商。
- 失败对用户返回稳定 `error_code` + 短中文；内部细节只在日志。

## 8. 错误与恢复

- 写接口必须幂等或有明确冲突码：同一用餐者重复取号返回已有票，不 500。
- 客户端重试仅限安全读和带幂等键的写；叫下一号用员工动作 id 或「仅当当前号仍为 X」条件，避免双击连叫两号。
- WebSocket 断线后：用 REST 拉快照再续订；以快照为准，事件只补差。
- 进程重启后队列以 PostgreSQL 为准，不从 Redis 恢复权威状态。

## 9. 测试与交付门禁

最低门禁（有代码后执行，现在标计划）：

1. 队列不变式契约：一人不能两张有效票；同窗口同日号不重复；人数 = waiting 数。
2. 权限：diner 不能叫号；staff 不能操作未授权窗口；display 不能写队列。
3. 过号：配置 0 不自动过号；>0 到期自动过号且不回队。
4. 实时：叫号后订阅者能收到事件（测试环境，不是 3000 压测）。
5. TTS：同一 `announcement_id` 客户端不重复播。

2000–3000 在线压测是独立性能门，未跑不得称达标。静态检查通过 ≠ 可上窗。

## 10. 安全最低线

- 用餐者浏览列表与取号都要会话（D22）。大屏只用独立展示令牌，可吊销；不能用员工写权限 cookie 暴露在电视上（D20）。
- 密码哈希（argon2id 或 bcrypt），不明文。
- 管理端导入学号：文件大小/编码限制，失败不半导入后静默。

## 11. 暂未采用
