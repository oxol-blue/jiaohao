# 演示脚本

按这个顺序走用餐者、员工、管理员和大屏。密码只放在本机 `.env`，不要写进聊天或截图。

演示数据：第一食堂（W1、W2）、第二食堂。账号来自环境变量 `ADMIN_STUDENT_ID`、`SEED_DINER_STUDENT_ID`、`SEED_STAFF_STUDENT_ID`。

1. 启动 API 和 Web。用餐者打开首页，未登录时看不到食堂列表。
2. 用餐者登录。应看到第一食堂和第二食堂。进入第一食堂，W1、W2 都在。
3. 在 W1 取号。再点一次，还是同一个号。再到 W2 取号，应被拒绝。
4. 员工登录。只能看到已授权窗口（W1），不能给 W2 叫号。
5. 员工对 W1 点「下一位」。用餐者页面变成已叫。再点一次「下一位」，应提示先完成或过号。用餐者此时不能取消。
6. 员工点「大屏链接」。用电视或另一个浏览器打开该链接。应看到当前号。刷新后不要把同一个号再播一遍。没有语音的浏览器仍要显示数字。
7. 员工点「完成」。大屏当前号清空或切到下一位。员工点「暂停取号」后，用餐者不能再取；点「恢复取号」后可以。
8. 管理员新建一个食堂并改名，再建一个没有叫号记录的窗口，然后删除窗口和食堂。有历史叫号的窗口删除应失败。
9. 管理员上传 CSV（表头 `student_id,display_name,role,password`，样例见 `docs/import-users.example.csv`）。新学号可以登录。同一文件再传一次，不应重复建账号。

同一套功能也可以不点页面，直接跑：

```powershell
cd apps/api
go run ./cmd/check
```

API 必须已经在 `127.0.0.1:8080`。这条命令不打印密码或令牌。
